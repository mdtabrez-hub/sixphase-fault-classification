# Six-phase fault classification benchmark — code

Code accompanying the six-phase transmission-line 178-class fault
classification study by B. Sehgal, D. K. Tiwari, S. P. Bihari and M. Tabrez.

Everything reported in the paper is produced by the Python modules in `src/`.
No MATLAB and no Simulink are required.

All data in the study were generated by simulation, deterministically from the
master seed **20260829**. No external or third-party data set was used, and there
is no separate data deposit: the case set, the feature matrix, the partition and
the representative waveform records are all regenerated by the single command
below, and the SHA-256 manifest in this release lets a reproduction be checked
without contacting the authors.

## Quick start

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

./reproduce.sh check      # seconds: line constants, transform, taxonomy, solver checks
./reproduce.sh all        # everything, including the full case set (several hours)
```

`reproduce.sh` is the single command named in the paper's data availability
statement. The case-set stage is chunked and resumable: each chunk checkpoints
into `out/Data/main/parts/`, and because every chunk is seeded from the master
seed and the chunk identifier alone, a run resumed after an interruption
produces the same case set as a single pass.

## Determinism

The master seed is **20260829** (Table 13). Operating points are drawn by a
scrambled Sobol′ sequence under that seed. With the pinned package versions in
`requirements.txt` the case set, the features, the partition and every reported
number reproduce exactly.

## Layout

```
reproduce.sh          single-command reproduction driver
requirements.txt      pinned package versions (Table 13)
src/
  sixphase_core.py    six-phase transform, modal decomposition, core checks
  compute_rlcg.py     line R, L, C, G matrices from the declared geometry
  spconst.py          system constants and derived line parameters
  spemt.py            electromagnetic-transient solver (Bergeron, trapezoidal)
  spcases.py          stress-matrix and operating-point generation
  enumerate_taxonomy.py  the frozen 178-class taxonomy enumerator
  taxonomy_full.csv   the frozen taxonomy (an input, not an output)
  spmeas.py           instrument-transformer and noise measurement chain
  sprelay.py          relay, including the Algorithm 1 feature layer
  runsim.py           case-set driver -> cases.csv and features.npy
  analyse.py          statistics and result tables
  classify.py         classifier benchmark, partitioning and attribution
  hif_ablation.py     high-impedance-fault index ablation and symmetry control
  hif_arc_regime.py   arc-current regime check
  validate.py         solver verification against independent solutions
  qc.py               internal consistency checks
  make_figures_v3.py  schematic figures
  makefigs_results.py result figures
  spwave.py           representative waveform records
  spstyle.py          shared plotting style
  verify_manuscript_numbers.py  cross-checks reported numbers against outputs
out/                  generated; not tracked in git (see the data deposit)
```

The feature layer of Algorithm 1 is `relay.features()` in `src/sprelay.py`. It
returns 85 elements per estimation window — six per-sequence current and voltage
magnitudes and angles, the sequence current and voltage energies, 30 guarded
inter-sequence magnitude ratios, 15 inter-sequence phase differences, and the
four scalars `H2`, `H3`, `eta_tr`, `eta_CT`. `runsim.py` stacks three
post-inception windows, giving the 255-element vector per case used by
`classify.py`.

## Scope of this release

This repository holds the computational pipeline only. Scripts used solely to
edit the manuscript file and build submission audit reports were deliberately
left out: they operate on the authors' Word document and reproduce nothing in
the paper.

## Verifying a reproduction

`SHA256SUMS.txt` lists the expected checksum of every file in the release.
After a run, compare your regenerated outputs against the manifest:

```bash
sha256sum -c SHA256SUMS.txt        # Linux
shasum -a 256 -c SHA256SUMS.txt    # macOS
```
